Example 1: Kids With the Greatest Number of Candies

In case you need to refer to the original problem statement, here is the link:

Kids With the Greatest Number of Candies - LeetCode

The input for each test case is:

  1. An array of integers denoting the number of candies each kid has
  2. An integer denoting the number of extra candies.

The problem boils down to this: for each kid, you need to determine if giving the kid all of the extra candies will make him/her have the greatest number of candies in the group. We need to output an array of booleans expressing this. The function signature is:

fun kidsWithCandies(candies: IntArray, extraCandies: Int): BooleanArray

In Kotlin, we can solve this in two lines:

fun kidsWithCandies(candies: IntArray, extraCandies: Int): BooleanArray {
    val maxCandies = candies.max()

    return BooleanArray(
        candies.size,
        { index -> candies[index] + extraCandies >= maxCandies!! }
    )
}

The last line is where all the magic happens:

return BooleanArray(
    candies.size,
    { index -> candies[index] + extraCandies >= maxCandies!! }
)

In it, we are constructing and returning a BooleanArray. The signature for the BooleanArray constructor is this:

BooleanArray(size: Int, init: (Int) -> Boolean)

The first argument to the constructor is the size of the array — candies.size in this case. The second argument is an init function, with the type (Int) -> Boolean — it takes in an Int (the index), and outputs a Boolean (the value to fill in at that index). We can encapsulate absolutely any initialization logic we want in this second argument.

Notice how convenient this is…Kotlin gives us a way to elegantly construct and initialize any array with just one line of code!

To further simplify this, there are two syntactic rules of Kotlin that we can make use of:

Passing trailing lambdas — “…if the last parameter of a function is a function, then a lambda expression passed as the corresponding argument can be placed outside the parentheses.”

So, we can simplify to this:

return BooleanArray(candies.size) { index ->
    candies[index] + extraCandies >= maxCandies!!
}
Implicit name of single parameter — “It’s very common that a lambda expression has only one parameter…The parameter will be implicitly declared under the name it"

So, we can simplify further to this:

return BooleanArray(candies.size) {
    candies[it] + extraCandies >= maxCandies!!
}

This is the final code. Take a few seconds to understand and internalize the syntax.

fun kidsWithCandies(candies: IntArray, extraCandies: Int): BooleanArray {
    val maxCandies = candies.max()

    return BooleanArray(candies.size) {
        candies[it] + extraCandies >= maxCandies!!
    }
}

Example 2: Chef and Price Control

Here is the link to the problem:

Contest Page | CodeChef

The input is:

  1. An array of integers denoting the original selling prices for a set of goods
  2. An integer denoting a new price ceiling that must be applied to all the goods.

We need to compute the total loss due to the introduction of the price ceiling. The problem boils down to this: for each good, if the ceiling is lower than the original price, we need to calculate the difference between the original price and the price ceiling, then output the sum of these values:

fun solve(prices: IntArray, priceCeiling: Int): Int

This is the one-line solution:

fun solve(prices: IntArray, priceCeiling: Int): Int {
    return prices.fold(0) { agg, e ->
        agg + (e- minOf(priceCeiling, e))
    }
}

The fold function allows you to aggregate the values in an array; fold iterates through the array, and applies the provided function to the aggregated value agg, and the next element e. The first argument to fold is what the aggregated value is initialized with— in this case, 0.

As you can see, this elegantly solves the problem in one line. Start with an aggregated value of 0, then keep adding e-minOf(priceCeiling,e) to the aggregated value. If the price ceiling did not cause the price of the good to fall, that expression will be 0, otherwise, it will be equal to the incurred loss for that good.

Example 3: Middle of the Linked List

Null values play an important role in many data structures. For example, in a Binary Tree, when a node has no left/right child, the value of the left/right attribute of the node is set to null. Similarly, you know you have reached the last node of a Linked List, when the next node is a null value.

Sometimes people have the perception that there are no nulls in Kotlin. But this is not true. Kotlin only requires you to be explicit about the nulls in your program. The official Kotlin documentation on Null Safety states:

Kotlin’s type system is aimed at eliminating the danger of null references from code

Whenever you assign a variable to a possibly null expression, the variable’s type must be nullable:

>>> val x = 3
>>> var y: Int = if (x>2) x else null
error: null can not be a value of a non-null type Int
>>> var y: Int? = if (x>2) x else null
>>> print(y)
3

Here, Int? is the nullable version of Int.

There are also ways to remove null values from your program. One such way is using the elvis operator, denoted by ?::

>>> var z: Int = y ?: 0
>>> print(z)
3

Note that despite y being of nullable type Int?, z is of type Int. As explained in the docs:

Elvis Operator — “If the expression to the left of ?: is not null, the elvis operator returns it, otherwise it returns the expression to the right. Note that the right-hand side expression is evaluated only if the left-hand side is null.”

In fact, the right side of the ?: doesn’t have to be an expression, and you don’t have to assign to a variable either:

>>> y ?: print("y is null")
3
>>> y = null
>>> y ?: print("y is null")
y is null

Armed with that basic understanding, let’s take a look at this last example problem:

Middle of the Linked List - LeetCode

We need to return the middle node of a singly Linked List given the head. We are also given this starter code:

class ListNode(var value: Int) {
    var next: ListNode? = null
}

The next property has a nullable type. This is because for the last node, next would have to be null.

We will solve this problem using the two pointer method. One pointer will iterate through the list twice as fast as the other. When the faster pointer reaches the end of the list, the slower pointer will be in the middle.

We’ll initialize the slow pointer at the first node and the fast one at the second:

fun middleNode(head: ListNode?): ListNode? {
    var slow = head
    var fast = head?.next ?: return head
    // TODO...
}

We have to do a 'safe call’ with head?.next instead of just head.next because head could be null (it is of nullable type); but don’t worry about that too much — Intellisense will tell you to make that change automatically. The important thing to notice is how we are using the elvis operator. In case there is no node after head, we know we have a Linked List of size one, and we can just return head.

For all other non-corner cases, we have the while loop:

fun middleNode(head: ListNode?): ListNode? {
    var slow = head
    var fast = head?.next ?: return head
    while(true) {
        slow = slow?.next
        fast = fast.next?.next ?: return slow
    }
}

We move the fast pointer two nodes ahead and the slow pointer one node ahead every time. If the fast pointer ever becomes null, that means it has reached the end of the Linked List and we can return the middle node.

Take a minute to understand and internalize the above syntax.

Kotlin vs Other Languages

Now that we’ve seen some examples, let’s have a more in-depth discussion of how Kotlin compares with other languages commonly used in Competitive Programming.

Kotlin vs Java

Kotlin is essentially an improvement of Java. It runs on the JVM just like Java, but it extends many Java classes — especially the Java Collections library — and it removes the need for a lot of boilerplate code.

Consider the Java ArrayList<Integer>, for example. Every time you want to add an int to the ArrayList, you first have to convert it to an Integer object. This is especially frustrating when you are in the middle of a contest.

Kotlin on the other hand has a very easy-to-use arrays system. There is an in-built class for each primitive-type array, as well as a parameterized Array<T> type, and they all come fully loaded with convenience and extension functions, as we have seen in the examples.

For a more exhaustive comparison, you can refer to this page from the official website.

Kotlin vs Python

We all know the fundamental problem with using Python for Competitive Programming — it is very slow. Because it is not compiled down to an executable, it is run line-by-line (this is what people mean when they say Python is an ‘interpreted’ language). This causes a very large performance overhead. Kotlin code is compiled and run in the JVM, so it is much faster.

But we don’t use Python because it is fast; we use it because it is easy to write. “It’s basically English!” we say. Well, I hope the examples have convinces you that Kotlin syntax is quite intuitive and English-like too. More importantly, Kotlin manages to do so while being type-safe (unlike Python, where you’ll often find yourself scratching your head wondering if the function you wrote took in a list or a tuple as an argument).

Kotlin vs C++

I know C++ has evolved a lot in recent years, and the syntax has become a lot more expressive. Despite that, I would advocate that Kotlin has at least two clear advantages that over C++:

  1. The functional syntax of Kotlin is exceptionally elegant. From what I’ve found on the web, it is far superior to that of C++.
  2. Kotlin has an REPL (like the Python console)! You can use it to quickly test out snippets of code. In C++, this is simply not possible without creating an executable or starting a debugger.

Kotlin vs C++: Performance

It is safe to say that if you are looking for raw speed, there is no better option than C++ right now. Once you’ve surmounted the initial learning curve and are vying for the top few spots in contests, you’ll have to switch to C++.

The main reason C++ is so fast is that it compiles down to an executable that is ‘native’ to the system. So if your online judge is running your C++ code on a Linux server, that code gets compiled and then run by Linux itself (this is why Windows and Linux come with different C++ compilers — MSVC and g++, respectively). Kotlin on the other hand, compiles the code down to the level of a JVM (which run on top of the OS). JVMs introduce abstractions to make it possible for the same Java code to run on any OS; unfortunately for us, these abstractions cause performance overhead.

But this could change in the future. There are a set of ‘Kotlin/Native’ compilers that compile Kotlin code down to an OS executable. Currently, Kotlin/Native compilers exist for Windows, Mac and Linux! Unfortunately, almost all online judges run Kotlin code in the JVM. Should this change in the future though, Kotlin will become truly comparable to C++ for competitive programming…even for the pros!

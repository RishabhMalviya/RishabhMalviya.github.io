One Trick for Phenomenally Smaller Unit Tests

A guide to writing *very* concise unit tests for your Python package.

The first section will explain the structure of the accompanying package and how to set it up on your system. If you just want to see examples of parametrization in PyTest, you can skip straight over to the second section, “Parametrizing Tests”.

Package Structure and Setup

The cloned repository will contain a package called efficient_dedup and a tests folder containing test cases.

The package is designed to perform efficient deduplication (remove duplicate values) in Python lists. It does this in two steps — first, it sorts the list, then it uses one of the deduplication algorithms to deduplicate the sorted list. Note that this package is just illustrative; as such, a lot of the code is functionally redundant. This is the package structure:

efficient_dedup
|
| - efficient_deduplication
| - deduplication_algorithms
| - sorting_algorithms
|
| - tests
    |
    | - test_efficient_deduplication

Parametrizing Tests

So, let’s summarize before proceeding. We have a context class called EfficientDeduplicator, which requires two strategies: a SortingAlgorithm and a DeduplicationAlgorithm. This context class has only one function, deduplicate_efficiently.

We would like to test deduplicate_efficiently with all possible combinations of the strategies, and on a few different test data. As we will see, it is possible to do all that in just one test case, if we make use of parametrization.

Parametrizing Over Data

This is the most basic test case we can write:

Let’s say we want to perform this test with a few different possible inputs, i.e., a few different values for the variable list_with_duplicates. First, we make list_with_duplicates an argument in the test function. Then, we provide a list of values for that argument through the @pytest.marker.parametrize decorator.

This is the general procedure for doing parametrization in Pytest:

  1. You specify the variable you want to parametrize over in the arguments list of the test function
  2. Then you use the @pytest.marker.parametrize decorator to provide a list of values for the variable.

Parametrizing over Classes

Now, let’s say we wanted to run the basic test with all possible different implementations of the DeduplicationAlgorithm, but keep the data the same. This can be achieved using a clever combination of Pytest parametrization, Python’s inspect module, and the fact that classes are first-class citizens in Python (meaning they can be passed around as arguments to functions).

To get a list of all the classes in the deduplication_algorithms module, we can import the module, and then run the following code:

print([
    getattr(deduplication_algorithms, name)
    for name, obj
    in inspect.getmembers(deduplication_algorithms)
    if inspect.isclass(obj)
])

which gives us a list of the classes in the module:
